1. Introduction 
1.1 Purpose 
The purpose of this document is to collect, analyze, and define high-level needs, features, and operational boundaries for SnapCode. It focuses on capabilities required by stakeholders and end users to build cross-platform code visually via block coding. 
1.2 Scope 
This Vision Document applies to SnapCode, a cross-platform visual block coding platform. SnapCode allows users to drag and drop blocks to form application logic that compiles directly into Flutter source code, which can then be compiled and run across multiple target platforms. 
1.3 Definitions, Acronyms, and Abbreviations 
• SnapCode: Cross-platform block coding application. 
AST (Abstract Syntax Tree): Tree representation of code structure parsed from visual block states. 
Block Coding: Visual drag-and-drop mechanics replacing text syntax with interlocking visual nodes. 
Flutter / Dart: Google's UI toolkit and programming language used for multi-platform compilation. 
Project Libre: The project management tool utilized to construct task schedules, Work Breakdown Structures (WBS), and Resource Breakdown Structures (RBS).

2. Positioning 
2.1 Business Opportunity 
With increasing demand for cross-platform apps, students and novice programmers encounter significant learning barriers due to complex framework syntax (e.g., Dart/Flutter setup). Traditional block platforms (like Scratch) teach basic programming logic but fail to output production-ready cross-platform code. SnapCode fills this gap by turning visual block layouts directly into executable Flutter code.
